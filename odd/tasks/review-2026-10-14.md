## Specs

### Bugs (the app does something the user did not ask for)

**S1 - `fetchPrintings` must not truncate silently.**
`src/shared/api/scryfallClient.ts:160-167` ignores `has_more`/`next_page`, and
Scryfall's `/cards/search` returns 175 objects per page. Measured live on
2026-10-14: `Forest` reports `total_cards: 956`, `has_more: true` and only 175
records come back, so the edition picker hides most printings of every basic land
with no message. Same fetch feeds `PrintingPicker`.
Acceptance: `fetchPrintings` follows `next_page` up to an explicit, documented cap;
consumers get loading and error states; hitting the cap is surfaced instead of
silently pretending to be the full list; requests stay inside Scryfall's ~10 req/s.
Check: vitest with a mocked two-page response (page 1 with `has_more: true`).

**S2 - Clearing the edition must clear the printing.**
`AddCard.tsx:175` maps an empty value to `null` but leaves `selectedPrinting` and
`selectedFinish` from the previous edition: the collector-number select then holds a
value with no matching option and `Agregar` stays enabled.
Acceptance: choosing `Seleccionar edición` resets printing and finish, the preview
disappears and `Agregar` is disabled; pinned by test.

**S3 - A want must be the card shown in the input.**
`WantEntryForm.tsx:137` computes `previewIsCurrent` but only `:206` uses it (to hide
suggestions): the preview at `:233` and `submit` at `:169` accept a stale preview, so
a want can be stored for a card that no longer matches the query.
Acceptance: the preview renders, and `submit` returns early, only while
`previewIsCurrent`; the pick and verify paths behave exactly as today.

**S4 - Adding an owned printing twice increments quantity.**
`binderStore.ts:39` appends unconditionally, so two adds of the same
`printingId + finish` produce two pockets even though the model carries `quantity`
and the grid renders a quantity badge; wants already dedupe.
Acceptance: `addEntry` finds an equal `printingId + finish` entry and adds to its
quantity (still capped at 99); a new combination still appends; the existing
append behaviour keeps its test.

### Improvements

**S5 - Persist a printing snapshot on `BinderEntry` (kills the grid's N+1).**
`CardSlot.tsx:25` resolves every pocket through `usePrinting`: 15 requests per page
to paint data the app already had at add time, and the binder cannot render without
the network. `WantEntry` already carries `name`/`typeLine`/`imageNormal`.
Acceptance: entries added after the change carry the printing snapshot and render
without a per-slot query; pre-existing entries keep a working fallback path.
Check: this changes the **persisted format** (high risk): a `migrate` on the zustand
store, no data loss on upgrade, old entries still rendering.

**S6 - AddCard must show loading and error states for printings.**
`AddCard.tsx:64` keeps only `data`: a slow or failed query leaves empty selects and
no explanation (a 429 looks like a broken modal).
Acceptance: spinner while pending, message plus recovery on error, empty result
explained.

**S7 - Dialog and menu keyboard/a11y gaps.**
`AddCard.tsx:157` and `CardZoom.tsx:74` listen for Escape on the dialog node, not on
`document`, so Escape stops working once focus leaves; no focus trap
(`AddCard.tsx:55` records it as a follow-up). `layout.tsx:66` declares
`role="menu"` + `menuitem` without arrow-key navigation and without restoring focus
to the trigger on close; `Mi cuenta` (`:67`, a non-focusable span) and `Cerrar
sesión` (`:87`) are dead controls.
Acceptance: Escape always closes, focus is trapped while the modal is open and
restored on close, the menu either honours the APG menu pattern or drops those
roles, and no dead control is left behind.

**S8 - Validation messages in Spanish.**
`WantEntryForm.tsx:15` renders zod 4 defaults in English ("Number must be greater
than or equal to 1") inside a Spanish UI.
Acceptance: every quantity error reads in Spanish; the schema still enforces
1..99 integer.

**S9 - Stop forcing a reflow on every pointer move.**
`useCardRock.ts:58` calls `getBoundingClientRect()` per `mousemove`.
Acceptance: the rect is measured on enter and cached, invalidated on leave/resize;
rocking behaviour is visually unchanged.

**S10 - Router error fallback.**
`router.tsx:21` has no `errorElement`: a failed lazy chunk (deploy with the tab
open) falls through to React Router's raw error output.
Acceptance: a friendly error screen with a retry/reload action on route load or
render failure.
